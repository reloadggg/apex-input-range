# Input Range · Apex 改键适应训练

[中文](README.md) · [English](README.en.md) · [日本語](README.ja.md)

[GitHub 源码](https://github.com/reloadggg/apex-input-range) · [MIT License](LICENSE)

React + TypeScript + Vite，通过浏览器 Gamepad API 读取 Xbox、DualShock 4（PS4）和 DualSense（PS5）手柄。支持键位导入、前后对照、高频动作与连续操作训练，无需后端或账号。

## 启动

**在线使用：https://apex.efastt.store/** · [备用地址](https://apex-input-range.pages.dev/)

无需安装，打开网址、连接手柄即可练习。首次使用请在「键位对照」导入自己的 Apex profile，内置键位只是示例。配置文件在浏览器内解析，每位用户的设置与记录保存在自己的浏览器中；localhost 的数据不会自动迁移到公开网站。

需要 Node.js 22.6+（推荐 Node.js 24）。

```powershell
npm install
npm run dev
```

在 Chrome / Edge 打开 **http://127.0.0.1:5173**
连接手柄后保持页面前台，按一下任意手柄键，唤醒浏览器识别。

## 界面语言

右上角下拉菜单支持 **中文 / English / 日本語**。训练提示、连招、键位对照、导入结果、帮助和历史日期会随语言切换；选择自动保存在当前浏览器。切换语言不改变配置、按键、训练进度或历史记录。

## Xbox / DS4 / DualSense

页面顶部「手柄键位显示」默认自动识别设备名称与 Sony 产品 ID，也可手动选择 Xbox、DualShock 4 / PS4、DualSense / PS5。PS 手柄示意图使用对称摇杆布局。

| Xbox | DS4 / DualSense |
| --- | --- |
| A / B / X / Y | × / ○ / □ / △ |
| LB / RB | L1 / R1 |
| LT / RT | L2 / R2 |
| LS / RS | L3 / R3（摇杆按下） |
| View | Share（DS4）/ Create（DualSense） |
| Menu | Options |

识别、提示、连招、手动录入、导入预览和前后对照使用一致的名称。切换显示不改动 Apex 动作绑定；历史记录保留训练时的手柄显示类型，旧记录按 Xbox 显示。

USB / 蓝牙连接需要浏览器提供 `standard` 映射。DS4Windows / Steam Input 若输出虚拟 Xbox，可手动选择 PS 显示；此选择只调整名称与图示，不会将非标准原始输入强行当成标准映射。自动识别支持 DS4 的 05c4 / 09cc 与 DualSense 的 0ce6 / 0df2 产品 ID，其他兼容手柄可手动选择显示。

PS 系统键、触摸板、麦克风键、震动与自适应扳机不参与训练。仅支持普通按键和扳机输入；Apex 的 PC 配置仍按文件中的物理槽位解析，不会自动替你迁移为主机版默认布局。

## 导入配置与前后对照

「键位对照」支持将多份文件拖入改前 / 改后上传框，预览后应用。只在浏览器解析，不上传、不修改原始 Apex 文件。

页面顶部有「找到 Apex 配置文件」引导：

1. 点击「复制 profile 路径」，按 **Win + R**，粘贴后回车；也可粘贴到资源管理器地址栏。
   ```text
   %userprofile%\Saved Games\Respawn\Apex\profile
   ```
2. 将 `profile.cfg` 拖到「改键后」上传框；如果有改键前保存的 `profile_backup.cfg`，拖到「改键前」。备份文件需由你事先保留；没有旧文件可直接手动填旧键位。
3. 检查识别结果和警告，再点击对应的「应用到…方案」。网页不能直接打开或扫描本机目录；需要你选择文件。

如果需要补充 `settings.cfg` / `settings_backup.cfg`，展开「可选：补充 settings 文件」，复制另一条目录：

```text
%userprofile%\Saved Games\Respawn\Apex\local
```

复制被浏览器阻止时，路径会自动选中，按 **Ctrl + C** 即可手动复制。

- 改后：`profile.cfg`，可同时加入 `settings.cfg`。
- 改前：`profile_backup.cfg`，可同时加入 `settings_backup.cfg`。没有旧文件时可手动输入。
- 通常位于 `%USERPROFILE%\Saved Games\Respawn\Apex\profile` 和 `local` 目录。
- `settings.cfg` 的 `+ability` 是槽位，实际自定义排列在 `profile.cfg` 的 `gamepad_custom_pilot`，是否生效由 `gamepad_button_layout` 决定。单独导入这类 settings 时会要求补充 profile。
- 支持标准布局 `0`、自定义布局 `6` 和可识别的直接动作绑定。其他预设、左右手交换、缺失或无效配置会提示；未识别动作保留原设置。忽略长按绑定，不执行配置中的命令。
- 大招按「战术技能 + 标记」生成，支持手动改为单键或双键。之后手动修改技能 / 标记时，可点击表格下方「大招 = 技能 + 标记」重新生成。

本次提供的 settings、profile 及 backup 中的手柄相关字段已提取到 `src/provided-configs.json`，不含玩家名等无关信息。首次升级自动作为新旧默认方案；之后保留用户修改。「载入本次提供的文件」可恢复快照。不是实时读取游戏目录，以后改键需重新导入。

| 动作 | 改前 | 改后 |
| --- | --- | --- |
| 跳跃 | A | LB |
| 蹲下 / 滑铲 | B | RB |
| 互动 / 换弹 | X | X |
| 战术技能 | LB | LS |
| 切枪 | Y | RS |
| 标记 | RB | Y |
| 冲刺 | LS | A |
| 近战 | RS | B |
| 大招 | LB + RB | LS + Y（按技能 + 标记生成） |

LS / RS 是摇杆按下。前后方案均可手动编辑，也支持手柄单键录入；组合键用第二个下拉菜单设置。

## 训练方式

训练首页的「连招训练」包含「混合训练」「我的弱项 / 自定义」入口，以及三个内置分类，共 11 组：

- **常用基础**：滑铲跳、跳跃接换弹、滑铲接换弹、实战串练。
- **交火衔接**：切枪补枪、蹲下换弹再开火、滑铲跳接开火、技能与大招切换。针对改键适应编排。
- **身法预习**：蹬墙跳、兔子跳、滑索跳的简化按键练习，附近期玩家教程的日期与章节链接。

点击分类，再选一组，下方会在同页展示整组动作与当前按键。点击「开始训练」，当前步骤高亮，完成后逐步点亮。固定练习一组，不受随机动作权重影响，重新打开页面会保留选中的组。所需动作未启用时，该组不可选择。

**混合训练**：在首页点击「混合训练」，勾选基础、交火、身法中的任意组，也可勾选已保存的自定义组。默认选择 11 组内置连招。每组等概率抽取，练完一整组才切换；有多组时不连续重复同一组。选择会自动保存，清空选择后不能开始。停用的动作组、含未启用动作或冲刺的组不会出题。混练不受随机专项的动作权重和连续比例影响。

**我的弱项 / 自定义**：点击「新建动作组」，自由填写名称，选择每一步动作，添加、删除或上下调整步骤，并设置到下一步的停顿（0–1.5 秒）。每组 2–12 步，最多保存 15 组。点击「保存并预览」，再点下方「开始训练」即可单独反复练；到「混合训练」勾选后也能混练。名称、步骤、停顿、启用状态都保存在当前浏览器。

这里的初始 5 组是可编辑示例，**不是系统根据成绩诊断出的弱项**。旧键冲突组依据改前 / 改后键位自动生成，例如原来跳键现在负责技能，就生成「跳跃 → 技能 → 跳跃」；训练历史只记录表现，不会自动改键或自动创建个人弱项。自定义组选择的是动作，每一步显示的物理按键由自己的当前方案决定；没有配置文件也能在「键位对照」手动录入按键。组的「随机专项频率」仅影响随机专项，混合训练仍为等概率抽取。

新增组的间隔为 0.2–0.45 秒，仅用于练习节奏，不代表游戏中的动作动画或身法判定窗口。身法预习不模拟地形、落地、摇杆或持续蹲姿；相同跳键必须松开后重新按下。完整身法需要结合教程进入游戏练习。[资料与选题说明](docs/combo-research.md)记录了来源和核对范围。

实战串练为：**技能 → 跳跃 → 滑铲 → 射击 → 蹲下 → 射击 → 换弹 → 换枪**。当前输入是 **LS → LB → RB → RT → RB → RT → X → RS**，步骤间停顿 0.2–0.45 秒，其中滑铲后停顿 0.45 秒再射击。过渡时显示倒计时，不接受新的答题输入；等下一步高亮再按。点击「随机专项」恢复混合练习。

- **按键识别**：显示物理按键，练习找键。
- **动作记忆**：显示游戏动作，按当前键位。题目默认隐藏按键答案，可以开启提示。
- **改键专项**：高频动作、改键冲突和连续动作训练。出现频率可设不练 / 普通 / 高频 / 重点（权重 0 / 1 / 3 / 5）；改过的动作可额外乘 3。

专项默认 80% 按动作组抽取，其余是单动作。这是**组的抽取概率**，不是输入次数占比。默认包含滑铲接换弹、跳跃接滑铲再换弹、跳跃与技能往返、技能接换弹、滑铲接大招。旧键改作其他动作时，自动生成「动作 A → 动作 B → 动作 A」练习。

按自动奔跑习惯，**冲刺不参与动作记忆、改键专项或连招训练**，已有设置中的冲刺频率也会同步归零。包含冲刺的旧动作组和自动冲突组合会跳过。配置对照仍保留冲刺的真实绑定，按键识别模式仍可练这个物理按键。

展开「连续动作与节奏」可编辑动作顺序、频率、启用状态，添加 / 删除动作组，调整连续比例和切题间隔（立即 / 120 / 240ms）。每组按顺序完成后再抽下一组；不练或未绑定的动作也不会出现在动作组中，没有可用组时回到单动作。专项动作选择独立于另外两种模式的物理按键范围。

## 输入与记录

只检测按下瞬间，长按不重复计分；扳机按下阈值 0.55、释放阈值 0.35。双键组合需有同时按住的重叠时刻，单独按其中一个不会计分或误判，按无关键算错。

按错保留题目，按对继续。反应时间包含纠错时间，暂停不计时。支持 30 / 60 / 120 秒或自由练习，Esc 或按钮暂停，切出页面 / 断开手柄自动暂停。

旧键习惯误触单独记录。最近 50 轮保留当时的动作、目标键、输入键、旧键和动作组，不受之后改键影响。可查看动作表现、连续动作切换表现和旧键误触，并导出 JSON。

手柄监视器可启用键盘体验，成绩单独标注且不计每日目标：A/B/X/Y 同名键，LB/RB = Q/E，LT/RT = 1/3，LS/RS = F/J，十字键 = 方向键，View/Menu = V/M。组合键同时按住对应键盘键。

只接受标准映射手柄。Elite / Edge 背键按映射的普通键识别，Xbox / PS 系统主键不参与，摇杆仅训练按压。不模拟移动、长按时长、技能冷却或战斗状态，也不向游戏发送输入。

数据在当前浏览器、当前地址的 localStorage；清理浏览器数据或更换地址会影响记录。网络用于首次安装依赖和可选字体，字体失败时使用系统字体。

## 公网部署

### Cloudflare Pages（当前部署）

当前使用 Cloudflare Pages **Direct Upload**，项目名为 `apex-input-range`。网站是纯静态资源，使用免费静态托管即可，无需 Functions、数据库或服务器。默认公网地址为 **https://apex-input-range.pages.dev/**。

自定义域名 **https://apex.efastt.store/** 已启用。对应 Cloudflare 的 `efastt.store` → **DNS → 记录**配置如下；HTTPS 证书由 Cloudflare 自动签发和续期。

| 类型 | 名称 | 目标 | 代理状态 | TTL |
| --- | --- | --- | --- | --- |
| CNAME | `apex` | `apex-input-range.pages.dev` | 已代理（橙云） | 自动 |

维护者首次部署需登录拥有该 Pages 项目的 Cloudflare 账号：

```powershell
npx wrangler@4.149.0 login --scopes account:read user:read pages:write
```

每次更新，在仓库根目录按顺序运行，前一步成功后再继续：

```powershell
npm ci
npm test
$env:VITE_BASE_PATH = '/'
npm run build
npx wrangler@4.149.0 pages deploy dist --project-name apex-input-range --branch main
```

推送 GitHub **不会自动更新当前 Direct Upload 网站**，需执行上面的构建和上传。若另建通过 Git 集成的 Pages 项目，可设置生产分支 `main`、构建命令 `npm run build`、输出目录 `dist`、环境变量 `NODE_VERSION=24`，不设置 `VITE_BASE_PATH`，由 Cloudflare 在推送后构建。现有 Direct Upload 项目不能直接切换成 Git 集成。

### GitHub Pages（可选手动发布）

仓库保留 `.github/workflows/pages.yml` 作为备用方案，仅手动触发，日常推送不运行。需要 GitHub Actions 可用，并在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**，再进入 **Actions → Deploy GitHub Pages (optional) → Run workflow**，选择 `main`。工作流运行单元测试、构建并发布，自动向 Vite 传入仓库子路径。当前在线站点使用 Cloudflare，不依赖此工作流。

不同域名的浏览器设置和历史各自独立，不会自动同步。

## 翻译维护

使用 i18next / react-i18next；`src/locales/messages.tsv` 每行依次为中文原文、英文、日文，以制表符分隔。`{{0}}`、`{{1}}` 等占位符必须保留。新增界面文案后运行 `npm run i18n:build`，会提取所需文案、检查缺失和占位符并生成 `en.json` / `ja.json`；生产构建会自动运行此检查。组件在渲染边界翻译，存储中的动作 ID 和绑定数据保持不变；用户文件名用 `translate="no"` 保留原文。
