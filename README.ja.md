# Input Range · Apex コントローラー練習

[中文](README.md) · [English](README.en.md) · [日本語](README.ja.md)

Apex のボタン配置変更に慣れるためのローカル練習アプリです。変更前後の比較、頻出アクション、連続操作を同じ画面で練習できます。React / TypeScript / Vite とブラウザーの Gamepad API を使用し、Xbox、DualShock 4、DualSense に対応します。アカウントやバックエンドは不要です。

## 起動

インストールせずに **https://reloadggg.github.io/apex-input-range/** から利用できます。コントローラーを接続し、**ボタン配置**で自分の Apex profile を読み込んでください。同梱の配置はサンプルです。ファイルは端末内で解析し、設定と履歴は各ブラウザーに保存します。localhost のデータは公開サイトへ自動移行されません。

Node.js 22.6 以降（Node.js 24 推奨）を使用してください。

```powershell
npm install
npm run dev
```

Chrome / Edge で **http://127.0.0.1:5173** を開きます。Windows では `启动训练器.cmd` のダブルクリックでも起動できます。コントローラーを接続し、ページを前面にした状態でいずれかのボタンを押すと認識されます。

右上のメニューで **中文 / English / 日本語** を切り替えられます。選択はブラウザーに保存され、ボタン配置、練習の進行状況、履歴はそのまま保持されます。

## Apex の設定を読み込む

**ボタン配置**を開くと、上部に設定ファイルの案内とパスのコピーボタンがあります。

1. 下のパスをコピーし、**Win + R** に貼り付けて Enter を押します。エクスプローラーのアドレスバーでも開けます。
   ```text
   %userprofile%\Saved Games\Respawn\Apex\profile
   ```
2. `profile.cfg` を**変更後**の枠へドロップします。変更前に保存した `profile_backup.cfg` があれば**変更前**へ読み込みます。バックアップがなければ以前の配置を手動入力できます。バックアップは配置変更前に自分で保存しておく必要があります。
3. 認識結果と注意事項を確認し、対応する設定への適用ボタンを押します。変更されるのは練習アプリ内の配置だけです。

必要に応じて `settings.cfg` / `settings_backup.cfg` も追加できます。補足設定の案内を展開し、次のフォルダーを開いてください。

```text
%userprofile%\Saved Games\Respawn\Apex\local
```

コピーがブラウザーに拒否された場合はパスが自動選択されるので、**Ctrl + C** でコピーしてください。ウェブページはローカルフォルダーを自動走査できません。ファイルはブラウザー内だけで解析し、送信・実行・書き換えは行いません。

カスタム配置の `settings.cfg` にある `+ability` はボタンのスロットです。実際の並びは `profile.cfg` の `gamepad_custom_pilot` にあり、`gamepad_button_layout` で有効な配置を判定します。対応する profile ファイルも読み込んでください。標準配置 `0`、カスタム配置 `6`、認識可能な直接バインドに対応します。未対応の配置、左右入れ替え、不完全なデータは警告を表示し、未認識のアクションは既存設定を保持します。長押し設定は無視します。アルティメットは**戦術アビリティ＋ピン**から生成し、手動編集も可能です。

同梱の個人情報を除いたスナップショットが初期配置になります。復元ボタンで同梱の配置に戻せますが、ゲームの現在のファイルを自動で読む機能ではありません。Apex 側を変更した後は再度読み込んでください。

## コントローラー

上部の表示設定は Xbox / DS4 / DualSense を自動認識し、手動選択もできます。DS4Windows / Steam Input が仮想 Xbox として出力する場合は PS 表示を選んでください。変更されるのは名称と図で、アクションの割り当ては保持されます。履歴には練習時の表示形式を保存します。

| Xbox | DS4 / DualSense |
| --- | --- |
| A / B / X / Y | × / ○ / □ / △ |
| LB / RB | L1 / R1 |
| LT / RT | L2 / R2 |
| LS / RS | L3 / R3（スティック押し込み） |
| View | Share / Create |
| Menu | Options |

USB / Bluetooth ともに、ブラウザーの `standard` マッピングが必要です。表示の手動選択で非標準の入力が有効になることはありません。システムボタン、タッチパッド、マイク、振動、アダプティブトリガーは練習対象外です。背面ボタンは割り当て先の通常ボタンとして認識されます。

## 練習

ホーム画面には**全11組**の連続操作があります。

- 基本：スライディングジャンプ、ジャンプからリロード、スライディングからリロード、8ステップの実戦シーケンス。
- 戦闘の連続操作：武器切り替えから射撃、しゃがみ・リロード・射撃、スライディングジャンプから射撃、アビリティとアルティメットの切り替え。
- 移動テクニックの予習：ウォールバウンス、バニーホップ、ジップラインジャンプの簡易入力。プレイヤーの解説動画の公開日と該当チャプターへのリンク付きです。

組を選ぶと全ステップと現在のボタンを表示します。**練習開始**を押し、ハイライトされた順に入力してください。実戦シーケンスは**アビリティ → ジャンプ → スライディング → 射撃 → しゃがみ → 射撃 → リロード → 武器切り替え**です。間隔は0.2～0.45秒で、次のハイライトまで入力を待ちます。連続ジャンプは一度ボタンを離してから押し直してください。

ここで練習するのはボタンの順番です。地形、移動、着地、しゃがみの維持、武器のアニメーション、アビリティのクールダウンは再現しません。技の完成はゲーム内で練習してください。[調査メモ](docs/combo-research.md)に出典と確認範囲を記載しています。

- **ボタン認識**：表示された物理ボタンを探します。
- **アクション記憶**：表示された動作に現在割り当てているボタンを押します。ヒントは任意です。
- **配置変更の練習**：頻出動作や変更した配置を重点的に練習します。頻度の重みは0 / 1 / 3 / 5で、変更した動作は追加で3倍にできます。以前のボタンが別の動作になった場合、往復シーケンスを自動生成します。

自動スプリントを前提に、**スプリントはアクションと連続操作の出題から除外**します。以前保存した組も対象です。比較表には実際の配置を残し、ボタン認識では同じ物理ボタンを練習できます。

詳細設定を開くと順序、頻度、有効状態、待ち時間を編集できます。既定の80%は「組を選ぶ確率」で、入力回数の割合ではありません。固定の連続操作はランダム出題の重みに影響されません。

## 入力と履歴

押した瞬間だけを判定し、長押しで繰り返し加点しません。トリガーのしきい値は押下0.55、解除0.35です。2ボタン同時押しは両方を押している時間が必要です。片方だけでは採点せず、無関係なボタンを押すとミスになります。

間違えると同じ問題を続け、正解すると次へ進みます。反応時間には訂正時間を含み、一時停止中は含みません。30 / 60 / 120秒または時間無制限を選択できます。Esc、画面のフォーカス喪失、コントローラー切断で一時停止します。直近50回を保存し、旧配置の誤入力やステップ間の切り替えを確認でき、JSONとして書き出せます。

コントローラーモニターでキーボード体験を有効にできます。A/B/X/Yは同名キー、LB/RBはQ/E、LT/RTは1/3、LS/RSはF/J、十字キーは矢印、View/MenuはV/Mです。体験の記録は区別され、コントローラーの1日目標には含みません。

設定と履歴は現在のブラウザー・アドレスのlocalStorageに保存します。ブラウザーデータの削除やアドレスの変更で保存内容が変わることがあります。任意の外部フォントが読み込めない場合はシステムフォントを使用します。ゲームへの入力送信は行いません。

## 開発と検証

### GitHub Pages で公開

`.github/workflows/pages.yml` が `main` を自動ビルド・公開します。**Settings → Pages → Build and deployment** で **GitHub Actions** を選んでください。プルリクエストでは単体テストとビルドのみ実行し、公開はしません。Node.js 24 を使用し、Pages のサブパスを Vite に渡すため、リポジトリ配下でも画像やスクリプトを正しく読み込めます。手動再公開は **Actions → Deploy GitHub Pages → Run workflow** から実行できます。

### 別の方法：Cloudflare Pages

Cloudflare の **Workers & Pages → Create application → Pages → Import an existing Git repository** を開き、`reloadggg/apex-input-range` へのアクセスを許可します。本番ブランチは `main`、ビルドコマンドは `npm run build`、出力先は `dist`、環境変数は `NODE_VERSION=24` に設定します。ルートディレクトリはリポジトリ直下とし、`VITE_BASE_PATH` は設定しません。**Save and Deploy** を押すと HTTPS の `*.pages.dev` アドレスが発行されます。その後は `main` の更新で自動公開されます。静的ホスティングだけを使うため、Functions、データベース、独自ドメインは不要です。

### ローカルでの確認

```powershell
npm run build
npm test
npm run test:e2e
```

ブラウザーテストはヘッドレスEdgeと標準ゲームパッドの模擬入力を使います。読み込み、配置変更、連続操作、同時押し、一時停止、表示形式、言語の保存、コピー失敗時の動作、モバイル表示を検証します。実機での接続確認の代わりにはなりません。

翻訳は `src/locales/messages.tsv` の中国語原文・英語・日本語の3列をタブ区切りで管理します。`{{0}}` などのプレースホルダーを保持してください。`npm run i18n:build` で必要な文言を抽出し、不足やプレースホルダーを確認してJSON辞書を生成します。本番ビルドでも自動実行します。保存済みIDやボタン割り当ては変更せず、画面描画時に翻訳します。ファイル名は `translate="no"` で原文を維持します。
